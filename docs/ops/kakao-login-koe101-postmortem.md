# 포스트모템 — 카카오 로그인 KOE101 (2026-07-27 ~ 2026-08-03)

웹 카카오 로그인이 KOE101(앱 관리자 설정 오류)로 막혔고, 해소까지 티켓 4건과
여러 라운드가 걸렸다. 원인은 5개였고 서로 층이 달랐다. 설정 절차 자체는
[`kakao-login-setup.md`](./kakao-login-setup.md) 를 보고, 이 문서는 **무엇이 원인이었고
어떻게 진단했어야 했는지** 만 다룬다.

## 결론 요약

| # | 층 | 원인 | 조치 | 티켓 |
|---|---|---|---|---|
| 1 | 앱 코드 | 웹이 OAuth `client_id` 를 **빈 값**으로 전송 | `KakaoSdk.init` 에 `javaScriptAppKey` 추가 | BC-26 |
| 2 | 배포 | 웹 빌드 파이프라인이 JS 키를 주입하지 않음 | `deploy-web.yml` 에 `--dart-define` 추가 | BC-34 |
| 3 | 콘솔 | JavaScript SDK 도메인 · 리다이렉트 URI · 활성화 · 동의항목 미설정 | 콘솔에서 등록 (사람) | — |
| 4 | 실행 | `dart-define` 은 **컴파일 타임 상수** — 재실행 없이는 반영 안 됨 | 프로세스 종료 후 재실행 | — |
| 5 | 실행 | `flutter run -d chrome` 의 **랜덤 포트**가 등록 도메인과 불일치 | `--web-port` 고정 | — |

1~3 을 다 고쳐도 4 때문에 "여전히 KOE101" 이 재현됐다. **이게 마지막 라운드를 소모한 원인이다.**

## 원인 상세

### 1. 웹이 `client_id` 를 빈 값으로 보냈다

Kakao Flutter SDK 는 플랫폼에 따라 서로 **다른 키**를 `client_id` 로 쓴다.

```dart
// kakao_flutter_sdk_common/lib/src/kakao_sdk.dart:23
static String get appKey => kIsWeb ? _jsKey : _nativeKey;
```

`main.dart` 는 `init(nativeAppKey: ...)` 만 호출했고, `_jsKey` 는 기본값 `""` 로 남았다
(`kakao_sdk.dart:112`). 네이티브는 정상 동작했으므로 **웹에서만** 재현됐다.

카카오 담당자가 KOE101 문의에 남긴 공식 답변이 정확히 이 지점을 가리킨다 —
["KOE101 오류 발생 시, URL에 `client_id` 파라미터 확인 부탁드립니다"](https://devtalk.kakao.com/t/koe101-firebase-sdk-uri/149417).

### 2. 파이프라인이 키를 주입하지 않았다

BC-26 은 `KAKAO_JAVASCRIPT_APP_KEY` 를 **소비하는** 코드만 넣고, 그 값을 **넘겨주는**
쪽(`deploy-web.yml`)은 손대지 않았다. 그래서 코드가 머지된 뒤에도 배포 웹은 여전히 빈 키로
나갔고, BC-34 가 파생됐다.

### 3. 콘솔 설정

카카오 콘솔은 리다이렉트 URI 를 **플랫폼 키 하위**에서 등록한다
(`[앱] > [플랫폼 키] > [JavaScript 키] > [리다이렉트 URI]`, REST API 키도 동일 구조).
"제품 설정 → 카카오 로그인" 하위가 아니다.

> 이번 해소 과정에서 JavaScript SDK 도메인과 리다이렉트 URI 를 **동시에** 등록했으므로,
> 둘 중 어느 쪽이 결정적이었는지는 분리 검증하지 않았다. 앱이 웹에서 보내는
> `redirect_uri` 는 실제 URI 가 아니라 문자열 `'JS-SDK'` 이므로
> (`kakao_flutter_sdk_user/user_api.dart:100-102` → `constants.dart:18`)
> 검증 기준은 도메인 쪽일 가능성이 높지만, 확증은 없다. 둘 다 등록하는 것을 권한다.

### 4. `dart-define` 은 컴파일 타임 상수다 — 재실행이 필요하다

```dart
// main.dart
const String _kakaoJavaScriptAppKey = String.fromEnvironment('KAKAO_JAVASCRIPT_APP_KEY', ...);
```

`String.fromEnvironment` 는 **컴파일 시점에 상수로 박힌다.** 따라서 아래는 모두 무효다.

| 시도 | 반영되는가 |
|---|---|
| 이미 실행 중인 앱에서 로그인 버튼 재클릭 | ✗ |
| hot reload (`r`) | ✗ |
| hot restart (`R`) | ✗ |
| `--dart-define` 없이 `flutter run` | ✗ |
| **프로세스 종료 후 `--dart-define` 포함 재실행** | ✓ |

콘솔 설정만 바꾼 경우와 구분해야 한다 — **콘솔 변경은 서버 측이라 앱 재빌드가 불필요**하고
로그인 재시도만으로 반영된다. 반면 키 주입은 앱 측이라 재컴파일이 필요하다.
이번엔 이 둘을 섞어서 "콘솔 설정했는데 여전히 안 된다" 가 됐다.

### 5. 웹 포트가 매번 달라진다

`flutter run -d chrome` 은 포트를 랜덤 배정한다. 카카오는 도메인을
`스키마 + 호스트 (+ 포트)` 단위로 검증하므로 포트가 바뀌면 등록값과 어긋난다.
`--web-port=8080` 처럼 고정하고, 그 값을 콘솔에 등록해야 한다.

`http://localhost:8080` 과 `http://127.0.0.1:8080` 은 카카오에게 **서로 다른 도메인**이다.

## 진단은 이렇게 했어야 했다

KOE101 을 만나면 **추측 전에 authorize URL 을 먼저 본다.** 에러 화면의 주소창에
거부된 요청의 파라미터가 그대로 들어 있다.

```
1. URL 의 client_id= 값을 확인
   ├─ 비어 있음        → 앱 측 키 주입 문제 (§1, §2, §4)
   └─ 값이 있음        → 2번으로
2. 그 값이 콘솔의 해당 플랫폼 키와 일치하는가
   ├─ 불일치          → 잘못된 키를 주입 중 (네이티브 키 ↔ JS 키 혼동)
   └─ 일치            → 3번으로
3. 플랫폼 등록 확인
   ├─ 웹              → JavaScript SDK 도메인 (포트·스키마 포함 정확히)
   ├─ Android         → 패키지명 + 키 해시 (디버그/릴리즈 별도)
   └─ iOS             → 번들 ID
4. 카카오 로그인 활성화 스위치 / 동의항목
```

에러 코드로도 층을 가를 수 있다.

| 코드 | 층 |
|---|---|
| KOE101 | `client_id` · 플랫폼 등록 · 활성화 계열 |
| KOE006 | 리다이렉트 URI 계열 |

**리다이렉트 URI 를 의심하기 전에 코드를 먼저 확인해야 한다** — KOE101 은 리다이렉트 URI
불일치로는 발생하지 않는다. 그건 KOE006 이다.

## 작업 방식 회고 (재발 방지)

원인 4·5 는 카카오 SDK 의 특성이지만, 아래는 **작업 방식 문제**였다.

### 재현 환경을 먼저 확정하지 않았다

플랫폼별로 쓰는 키가 다른데(`appKey` 게터), 어느 환경에서 재현되는지 묻지 않고
전 플랫폼을 대상으로 추정 수정을 했다. "웹입니까 / Android 입니까 / iOS 입니까" 한 줄이면
원인 후보가 1/3 로 줄었고, 실제로 그 질문을 한 라운드에서 원인이 특정됐다.

→ **KOE101 류 보고를 받으면 첫 질문은 재현 환경이다.**

### 배선을 끝까지 하지 않았다

BC-26 에서 `dart-define` 을 **읽는** 코드만 넣고 **넘기는** 쪽을 PR 리스크 항목에
"배포 시 주입 필요" 로만 적었다. 결과적으로 머지 후에도 증상이 그대로여서 BC-34 가 생겼다.

→ **설정값을 새로 도입하면 정의·주입·소비·문서를 한 티켓에서 닫는다.**
   (로컬 실행 명령 / CI 워크플로 / 시크릿 문서까지)

### 콘솔 구조를 확인하지 않고 문서를 썼다

`kakao-login-setup.md` 초판에 리다이렉트 URI 를 "제품 설정 → 카카오 로그인" 하위로,
웹 항목을 "서비스 도메인 + 콜백 경로" 로 적었다. 둘 다 실제 콘솔과 달랐고,
존재하지 않는 콜백 경로를 찾게 만들었다. 코드 근거(`redirect_uri='JS-SDK'`)는 맞았지만
그것으로 "등록 대상이 아니다" 까지 단정한 것은 과했다.

→ **외부 콘솔 절차를 문서화할 때는 실제 화면 또는 공식 문서로 대조한다.**
   코드에서 읽은 사실로 콘솔 UI 를 추론하지 않는다.

### 백그라운드 실행 로그를 파이프로 잘라 증거를 잃었다

검증용으로 `flutter run ... | tail -40` 을 백그라운드로 띄웠다. `tail` 은 EOF 까지
버퍼링하므로 로그 파일이 계속 비어 있었고, 붙여둔 모니터가 아무 것도 관측하지 못했다.
성공 여부는 사용자 확인에 의존해야 했다.

→ **백그라운드 실행은 출력을 그대로 남긴다.** 필터가 필요하면
   `grep --line-buffered` 처럼 라인 단위로 흘려보내는 도구를 쓴다.

## 검증된 최종 상태

- 로컬 웹: `flutter run -d chrome --web-port=8080 --dart-define=KAKAO_JAVASCRIPT_APP_KEY=<js_key>` → 로그인 성공
- 배포 웹: `deploy-web.yml` 이 `secrets.KAKAO_JAVASCRIPT_APP_KEY` 주입 (BC-34)
- 네이티브(Android/iOS): 콘솔 키 해시·번들 ID 등록 필요 — 미검증
