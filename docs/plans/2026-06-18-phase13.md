# Phase 13 — 앱스토어 제출 준비 & 소프트 런치

## 1. 배경

Phase 12(`v0.9.0`)에서 독서 경험 심화와 수익화 인프라가 완성됐다.
이제 앱스토어 제출에 필요한 마지막 준비를 완료하고 소프트 런치한다.
CLAUDE.md §7.1에 따라 앱스토어 출시 시점에 `v0.1.0`으로 승격한다.

**Phase 13 전략**:

1. **기술 부채 청산** — Phase 12 전환 리뷰에서 편입된 항목(page_count, M2 리뷰 통합, RevenueCat SDK).
2. **앱스토어 준비** — 스플래시·아이콘 완성, 온보딩 플로우, 개인정보처리방침 화면, 앱 심사 요구사항.
3. **배포 파이프라인** — GitHub Actions CI 완성(lint·test·build), Fly.io 프로덕션 배포 자동화.
4. **소프트 런치** — TestFlight(iOS) + Google Play 내부 테스트 배포, `v0.1.0` 태그.

## 3. M56 — 기술 부채 청산

### 3.1 목표

Phase 12에서 미완성으로 남긴 항목 3가지를 정리한다.

### 3.2 구현 범위

**page_count 추가**:
- Migration: `books` 테이블에 `page_count INT` 컬럼 추가 (nullable, 기존 데이터 NULL 허용).
- 네이버/카카오 책 API 응답에서 `page_count` 파싱하여 저장.
- `ClubReadingPlan` weekly_pages 계산이 실제 페이지 수를 사용하도록 수정.

**M2 리뷰 통합**:
- `POST /me/library/{book_id}/review` (한줄 리뷰) 엔드포인트 폐기 → M54 `book_reviews` 로 대체.
- Flutter `_MyReviewCard` (UserBook 기반) → `WriteReviewSheet` (M54) 로 교체.
- `BookApi.getBookReviews` / `BookReviewDto` 등 데드 코드 제거.

**RevenueCat SDK 실 연동**:
- `purchases_flutter: ^8.0.0` pubspec 추가.
- `PaywallScreen`의 `subscriptionNotifier.verify()` 방식 → `Purchases.purchasePackage()` 방식 교체.
- Entitlement: `pro` (월간 + 연간 공통).

## 4. M57 — 앱스토어 메타데이터 & 온보딩

### 4.1 목표

앱스토어 심사에 필요한 UI 요소와 법적 필수 화면을 완성한다.

### 4.2 구현 범위

- **온보딩 플로우**: 앱 첫 실행 시 3장 슬라이드 (기록/성장/대화 컨셉) → 로그인 화면.
- **개인정보처리방침 & 이용약관**: 인앱 WebView 화면 (`/legal/privacy`, `/legal/terms`).
- **앱 아이콘**: 현재 Flutter 기본 아이콘 → 브랜드 아이콘 (book + timer 컨셉, flutter_launcher_icons).
- **스플래시**: flutter_native_splash 적용 (브랜드 배경색 + 로고).
- **앱스토어 심사 계정**: 심사용 테스트 계정 안내 화면 (설정 → 개발자 메뉴).

## 5. M58 — CI/CD 파이프라인 완성

### 5.1 목표

모든 PR에서 자동으로 품질을 검증하고 main merge 시 자동 배포되도록 한다.

### 5.2 구현 범위

**GitHub Actions**:
- `backend.yml`: ruff check, mypy, pytest (testcontainers Postgres), Docker build 검증.
- `mobile.yml`: dart analyze, flutter test, flutter build ios --no-codesign, flutter build apk.

**Fly.io 자동 배포**:
- `deploy.yml`: main push 시 `fly deploy --remote-only` 실행.
- Alembic migrate 자동 실행 (release_command).
- Fly.io secrets 관리 가이드 (`docs/ops/fly-secrets.md`).

## 6. M59 — 프로덕션 배포 & 모니터링

### 6.1 목표

실제 프로덕션 환경에 배포하고 Sentry/Grafana로 안정성을 확인한다.

### 6.2 구현 범위

- Sentry production 환경 DSN 설정.

- `/health` 엔드포인트 응답 확인 및 Fly.io health check 연결.
- Grafana 대시보드 프로덕션 지표 초기 캡처.
