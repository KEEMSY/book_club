# Book Club — Phase 4 구현 계획

## 1. 배경 및 목표

Phase 3(M12–M15)에서 챌린지 달성 판정·위시리스트·하이라이트·QA까지 완료됐다.
Phase 3 이후 추가 폴리시로 서재 하이라이트 탭·커뮤니티 인용 탭·CTA 버그 수정까지 반영됐다.

Phase 4는 앱스토어 출시(`v0.1.0`) 전 마지막 기능 레이어다. 핵심 목표:

1. **책 추천**: 독서 이력·커뮤니티 데이터 기반 추천으로 "다음 책" 탐색 경험 제공.
2. **독서 그룹 & 모임**: 소수 인원의 프라이빗 독서 그룹 + 온/오프 모임 이벤트 RSVP.
3. **공개 프로필**: 팔로워에게 독서 기록·배지·하이라이트를 선별 공개.
4. **QA·스토어 제출**: 전체 플로우 재검증 → App Store / Play Store 제출 → v0.1.0.

## 3. M16 — 책 추천 & 탐색 강화

### 3.1 목표

"다음에 무슨 책 읽지?"를 앱 안에서 해결한다. ML 파이프라인 없이 규칙 기반으로 시작하고,
데이터가 쌓이면 Phase 5에서 협업 필터링으로 업그레이드할 경로를 열어둔다.

### 3.2 백엔드

**추천 도메인 (`app/domains/discovery/`)** 신설:

```
discovery/
  models.py        — RecommendationReason (enum: GENRE_MATCH, COMMUNITY_POPULAR, SIMILAR_READERS)
  service.py       — RecommendationService
  repository.py    — RecommendationRepository
  router.py        — GET /me/recommendations
  schemas.py       — RecommendedBook, RecommendationResponse
  providers.py
```

**추천 로직 (규칙 기반 3가지 소스):**

| 소스 | 설명 | 알고리즘 |
|---|---|---|
| `GENRE_MATCH` | 내가 완독한 책의 장르를 가장 많이 읽은 독자들이 읽은 다음 책 | `user_books` JOIN + `book_metadata.genre` |
| `COMMUNITY_POPULAR` | 최근 7일 커뮤니티에서 가장 많이 포스팅된 책 | `posts.book_id` COUNT |
| `SIMILAR_READERS` | 나와 공통 완독 책 >= 2권인 유저들이 읽은 책 (내가 아직 안 읽은 것) | 교집합 기반 |

최대 15권, 중복 제거, 이미 서재에 있는 책 제외.

**책 메타데이터 보강:**

- `books` 테이블에 `genre TEXT[]` 컬럼 추가 (Alembic 마이그레이션)
- 네이버 책 API 응답의 `category` 필드 파싱 → 저장

### 3.3 모바일

**탐색 탭 (기존 커뮤니티 탭 옆에 "탐색" 탭 추가):**

```
BottomNavigationBar
  홈 (타이머/대시보드)
  서재
  커뮤니티
  탐색        ← NEW
  프로필
```

**탐색 화면 구조:**
- 상단: "이런 책 어때요?" — 추천 책 가로 스크롤 카드 (최대 6권)
- 중간: "커뮤니티에서 화제" — 최근 7일 인기 책 그리드
- 하단: 기존 책 검색 기능 통합

### 3.4 테스트

- `RecommendationService` 단위 테스트:
  - 장르 매칭 추천: 이미 서재에 있는 책 제외 검증
  - 커뮤니티 인기: 7일 외 포스트 제외 검증
  - 유사 독자: 공통 완독 < 2권이면 결과 없음 검증
- `GET /me/recommendations` 라우터 통합 테스트

## 4. M17 — 독서 그룹 & 모임

### 4.1 목표

2–10명의 소규모 독서 모임을 앱 안에서 조직·운영한다.
온라인(화상·채팅)과 오프라인(장소) 모임 모두 지원.

### 4.2 데이터 모델

**신규 도메인 `app/domains/club/`:**

```sql
reading_clubs
  id          UUID PK
  name        TEXT
  description TEXT NULL
  owner_id    UUID FK(users)
  book_id     UUID FK(books) NULL   -- 현재 함께 읽는 책 (optional)
  is_private  BOOLEAN DEFAULT true
  max_members INT DEFAULT 10
  created_at  TIMESTAMPTZ

club_members
  club_id     UUID FK(reading_clubs)
  user_id     UUID FK(users)
  role        TEXT  -- 'owner' | 'member'
  joined_at   TIMESTAMPTZ
  PRIMARY KEY (club_id, user_id)

club_events
  id          UUID PK
  club_id     UUID FK(reading_clubs)
  title       TEXT
  description TEXT NULL
  event_type  TEXT  -- 'online' | 'offline'
  location    TEXT NULL   -- 오프라인 장소 또는 화상 링크
  scheduled_at TIMESTAMPTZ
  created_by  UUID FK(users)
  created_at  TIMESTAMPTZ

event_rsvps
  event_id    UUID FK(club_events)
  user_id     UUID FK(users)
  status      TEXT  -- 'going' | 'maybe' | 'not_going'
  PRIMARY KEY (event_id, user_id)
```

### 4.3 백엔드 API

```
POST /clubs                           — 그룹 생성
GET  /clubs/{id}                      — 그룹 상세
GET  /me/clubs                        — 내 그룹 목록
POST /clubs/{id}/members              — 초대 코드 또는 직접 추가
DELETE /clubs/{id}/members/{user_id}  — 멤버 제거 (owner 전용)
PATCH /clubs/{id}                     — 그룹 정보 수정

POST /clubs/{id}/events               — 모임 생성
GET  /clubs/{id}/events               — 모임 목록
POST /clubs/{id}/events/{event_id}/rsvp — RSVP 상태 변경
```

### 4.4 알림 연동

- 모임 생성 시 멤버 전원 푸시 알림
- 모임 24시간 전 리마인더 알림 (FCM scheduled message)
- 새 멤버 초대 알림

### 4.5 모바일

- 탐색 탭 하단에 "내 독서 그룹" 섹션
- 그룹 상세: 멤버 목록 + 현재 읽는 책 + 예정 모임 카드
- 모임 카드: 날짜·장소·RSVP 버튼(갈게요 / 아마도 / 못가요)
- 그룹 생성 흐름: 이름 → 함께 읽을 책(선택) → 멤버 초대

### 4.6 테스트

- `ClubService` 단위 테스트: 멤버 초대·제거, 모임 생성, RSVP 상태 전이
- RSVP 중복 처리 (같은 유저 RSVP 변경)
- 정원 초과 멤버 추가 거부 검증

## 5. M18 — 공개 프로필 강화

### 5.1 목표

팔로워·팔로잉 관계가 있는 유저끼리 독서 기록·배지·하이라이트를 선별 공개한다.
현재 프로필은 나만 보이는 상태; 이번에 공개 프로필 페이지를 완성한다.

### 5.2 백엔드

**`/users/{id}/profile` 엔드포인트 보강:**

```
GET /users/{id}/profile
  → nickname, profile_image_url
  → 공개 통계: 완독 권수, 독서 시간 합계, 현재 등급, 연속 독서 일수
  → 공개 배지 목록 (최대 6개, 사용자가 선택한 것)
  → 최근 공개 하이라이트 (최대 5개)
  → 최근 공개 포스트 (최대 10개)
```

**프로필 공개 설정:**

- `users` 테이블에 `profile_visibility TEXT DEFAULT 'followers'` 추가
  - `'public'` — 모두 공개
  - `'followers'` — 팔로워만 (기본)
  - `'private'` — 나만

- 하이라이트·포스트 개별 공개 여부: 기존 `is_public BOOLEAN` 활용

**배지 pinning:**

- `user_badges` 테이블에 `is_pinned BOOLEAN DEFAULT false` 추가
- `PATCH /me/badges/{badge_id}` — pinned 토글

### 5.3 모바일

- **내 프로필 화면** 개편: 통계 카드(완독·시간·등급·스트릭) + 배지 진열장(핀 배지 최대 6개) + 최근 하이라이트
- **타인 프로필 화면**: 공개 설정에 따른 조건부 렌더링. 팔로우 버튼 (기존 소셜 기능 연결)
- **배지 관리**: 배지 목록에서 "프로필에 고정" 토글

### 5.4 테스트

- `profile_visibility = 'private'` 유저 프로필 → 팔로워 아닌 유저는 통계 빈 값 반환 검증
- 배지 핀 최대 6개 초과 시 에러 검증

## 8. 아키텍처 고려사항

### 8.1 discovery 도메인 경계

- `RecommendationService`는 `book` 도메인 Repository에 직접 접근 금지.
- `FeedBookQueryPort`와 동일한 패턴으로 `DiscoveryBookQueryPort` 정의.
- `reading` 도메인 완독 데이터는 `DiscoveryReadingQueryPort`로 읽는다.

### 8.2 club 도메인 알림 연동

- `ClubService`는 `NotificationPort`를 주입받아 이벤트 발생 시 호출.
- 모임 리마인더는 Redis delayed job 또는 APScheduler 기반 스케줄러.

### 8.3 프로필 공개 권한

- `profile_visibility` 체크는 Router에서 수행 (Service는 가시성 무관하게 데이터 반환).
- 팔로워 여부는 `SocialService.is_following(viewer_id, target_id)` 호출로 위임.
