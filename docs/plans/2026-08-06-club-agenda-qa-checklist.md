# 발제문 모임 QA 체크리스트 (BC-42)

에픽 BC-42(회차·발제문·논제 스레드·AI 추천)의 수용 기준 검증 시트.
백엔드는 CI(pytest + alembic + docker)로, 모바일은 위젯 테스트로 이미 자동 검증됨.
아래는 **실서버 end-to-end(수동/Chrome MCP)** 확인 항목이다.

## 사전 조건
- 백엔드 스택 기동: `docker compose up -d` (또는 워크트리 격리 스택 `scripts/worktree-stack.sh`), `alembic upgrade head`(0052까지).
- 모바일: `flutter run`(모바일) 또는 `flutter run -d chrome`(웹, Chrome MCP E2E).
- 로그인(카카오/Apple) 후 모임(공개/비공개) 최소 1개 보유, 책 카탈로그 존재.

## 시나리오 1 — 회차 생성·발제자 지정 (BC-44)
- [ ] 호스트가 모임 상세 → 회차 탭에서 회차 생성(책 선택, 제목, 범위)
- [ ] 회차 목록이 **책별로 그룹**되어 표시, 상태 배지(draft/open/closed)
- [ ] 호스트가 회차에 발제자 지정/해제
- [ ] 상태 전이 draft→open→closed, 역행/무효 전이 거부(비-host 거부)
- [ ] 비-호스트에게 생성·상태전이·발제자지정 액션이 노출되지 않음

## 시나리오 2 — 발제문·논제 작성/게시 (BC-45, BC-50)
- [ ] 호스트 또는 발제자만 발제문 에디터 진입(그 외 "권한 없음" 안내)
- [ ] 본문 작성 + 논제 N개 추가/삭제/**드래그 정렬**
- [ ] 논제 없거나 본문 비면 게시 버튼 비활성
- [ ] 임시저장(draft) → 게시(published) 전이, 재게시 시도 거부(409)
- [ ] 게시된 발제문이 회차 상세에 논제 아코디언으로 표시

## 시나리오 3 — 논제 스레드 토론 (BC-46, BC-51)
- [ ] 멤버가 논제별 답글 작성, 1단계 대댓글 작성
- [ ] 2단계(대댓글의 대댓글) 작성 액션이 노출되지 않음(1단계 캡)
- [ ] 본인 답글에만 수정·삭제 노출(수정 시 "(수정됨)" 표기)
- [ ] 타인 답글엔 수정·삭제 미노출
- [ ] 답글 수 카운트가 논제 타일별로 정확히 증감

## 시나리오 4 — feed·알림 (BC-47, BC-48, BC-52)
- [ ] 회차 open / 발제문 게시 / 답글 작성 시 feed 이벤트 생성
- [ ] 피드에 3종 카드(session_opened/agenda_published/discussion_commented) 렌더, 탭 시 **회차 상세로 딥링크**
- [ ] 발제문 게시 → 멤버에게 푸시, 내 발제문/논제에 답글 → 작성자에게 푸시(본인 제외)
- [ ] 푸시 탭 → 해당 회차/논제로 라우팅(topic_id 있으면 논제 자동 확장·스크롤)

## 시나리오 5 — AI 논제 추천 (BC-53, BC-60)
- [ ] 발제문 에디터에서 "AI 추천" → 책+범위 기반 논제 후보 3~5개 표시
- [ ] 후보 선택 → 논제 입력에 프리필, 저장은 기존 add_topic 경유(추천 자체는 미저장)

## 시나리오 6 — 권한·유료 훅 회귀
- [ ] 공개 모임은 비멤버도 열람, 비공개는 멤버만
- [ ] 유료 훅 컬럼(access_type 등)은 UI/동작에 아무 영향 없음(현재 전부 open/included)

## E2E 실행 기록
- 자동(CI): 백엔드 pytest+alembic, 모바일 analyze+widget test — **PR #27~#43 전부 green**.
- 수동/Chrome MCP: 로컬 백엔드+웹 기동 필요. 실행 시 결과·스크린샷을 본 섹션에 첨부.
  - 상태: ⏳ 로컬 스택 기동 후 수행 예정(참조: 메모리 e2e_verification, `docs/plans/2026-04-26-m6-qa-checklist.md`).
