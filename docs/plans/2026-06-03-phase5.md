# Book Club — Phase 5 구현 계획

## 1. 배경 및 목표

Phase 4(M16–M19)에서 앱스토어 출시(`v0.1.0`)까지 완료됐다. 이제 출시 이후 첫 번째 기능 레이어다.

Phase 5는 세 축을 중심으로 진행한다:

1. **기술 부채 해소**: Riverpod 3.0 마이그레이션, 타입 어노테이션 보강, 의존성 업그레이드.
2. **추천·통계 심화**: ML 기반 추천(협업 필터링)과 상세 독서 통계로 StoryGraph 대비 경쟁력 확보.
3. **소셜 공유 루프**: 연말 독서 회고 카드, 서재 SNS 캡처 최적화로 유기적 바이럴 채널 구축.

Phase 6 이후를 위해 그룹 채팅(실시간) 인프라와 ML 파이프라인 경로를 설계 단계에서 열어둔다.

## 3. M20 — 기술 부채 정리

### 3.1 목표

Phase 5 기능 개발 전 코드베이스 건강도를 높인다. 모든 항목은 사용자에게 보이지 않지만 이후 마일스톤의 유지보수 비용에 직결된다.

### 3.2 Riverpod 3.0 마이그레이션

Riverpod 3.0에서 `StateProvider`, `StateNotifierProvider`, `ChangeNotifierProvider`가 `package:riverpod/legacy.dart`로 이동됨. 신규 코드에서 사용 비권장.

**마이그레이션 패턴:**

```dart
// Before (legacy)
final counterProvider = StateNotifierProvider<CounterNotifier, int>(...);
class CounterNotifier extends StateNotifier<int> { ... }

// After (Riverpod 3.0)
@riverpod
class Counter extends _$Counter {
  @override
  int build() => 0;
  void increment() => state++;
}
```

**작업 범위:**
- `mobile/lib/` 전체 grep → `StateNotifierProvider` / `StateProvider` 사용 위치 목록화
- 도메인별 순차 마이그레이션 (auth → reading → feed → 나머지)
- 마이그레이션 완료 후 `import 'package:riverpod/legacy.dart'` 0건 확인

### 3.3 discovery/service.py 타입 어노테이션

현재 3곳에 `# type: ignore[type-arg]`가 있으며 raw `dict`를 반환.

```python
# Before
def get_recommendations(self, user_id: UUID) -> list[dict]:  # type: ignore[type-arg]
    ...

# After
from typing import TypedDict

class RecommendedBookItem(TypedDict):
    book_id: str
    title: str
    reason: str
    score: float

def get_recommendations(self, user_id: UUID) -> list[RecommendedBookItem]:
    ...
```

**확인 게이트**: `mypy --strict app/domains/discovery/` 경고 0.

### 3.4 FCM HTTP v1 어댑터 업그레이드

`backend/app/domains/notification/adapters/fcm_push_adapter.py`의 TODO 처리.

- FCM Legacy HTTP API → HTTP v1 API 전환
- `google-auth` 라이브러리로 OAuth 2.0 Bearer 토큰 발급
- `POST https://fcm.googleapis.com/v1/projects/{project_id}/messages:send`
- 기존 Contract 테스트 픽스처 업데이트

### 3.5 retrofit/freezed 버전 업그레이드

현재 `retrofit: '>=4.4.1 <4.5.0'` 제약이 freezed 2→3 마이그레이션 없이는 해제 불가.

**작업 순서:**
1. freezed 2 → 3 마이그레이션 (breaking: `copyWith` 생성 방식 변경)
2. 코드 재생성: `dart run build_runner build --delete-conflicting-outputs`
3. retrofit 버전 제약 해제 후 최신 호환 버전으로 업그레이드
4. `dart analyze` 경고 0 확인

### 3.6 DevLoginButton 교체

`mobile/lib/features/auth/presentation/login_screen.dart`에서 `DevLoginButton` → `KakaoLoginButton` 복원.

- `dev_login_button.dart` 파일 삭제 또는 debug 모드 전용 위젯으로 격리
- `auth_e2e_test.dart` 연관 TODO 주석 처리

### 3.7 테스트

- mypy strict 통과 (discovery 도메인)
- FCM 어댑터: HTTP v1 요청 형식 Contract 테스트
- flutter test 전체 통과 (Riverpod 마이그레이션 후 회귀 없음)

## 4. M21 — 독서 통계 심화 & ML 추천

### 4.1 목표

StoryGraph의 핵심 차별점인 상세 독서 통계와 개인화 추천을 구현한다. 규칙 기반(Phase 4)에서 협업 필터링으로 업그레이드.

### 4.2 독서 통계 탭 강화

**현재**: 독서 히트맵 + 등급 정도.
**목표**: StoryGraph 수준의 다차원 통계.

**신규 통계 항목:**

| 지표 | 계산 방식 | 표현 |
|---|---|---|
| 평균 독서 속도 | `session_duration / pages_read` | 분/페이지, 페이지/시간 |
| 포맷별 비중 | `user_books.format` 집계 | 종이책 / 전자책 / 오디오북 파이 차트 |
| 누적 독서 시간 | `SUM(session_duration)` | 시간 단위, 월별 막대 차트 |
| 장르 분포 | `books.genre[]` 집계 | 상위 5개 장르 도넛 차트 |
| 평균 완독 기간 | `completed_at - started_at` | 책당 평균 일수 |

**백엔드:**

```
GET /me/reading-stats
  → speed: { avg_minutes_per_page, avg_pages_per_hour }
  → format_breakdown: { paper: int, ebook: int, audio: int }
  → monthly_hours: [{ month: "2026-01", hours: float }, ...]
  → genre_breakdown: [{ genre: str, count: int }, ...]
  → avg_completion_days: float
```

**모바일:**
- 서재 탭 내 "통계" 서브탭 추가 (기존 히트맵 탭과 통합)
- 차트 라이브러리: `fl_chart` (이미 의존성에 있는 경우 재사용, 없으면 추가)
- 공유 가능한 통계 카드 스냅샷 (`RepaintBoundary` + `toImage`)

### 4.3 ML 기반 추천 (협업 필터링)

Phase 4의 규칙 기반 3소스를 ML로 보강. 초기에는 경량 모델, 데이터가 쌓이면 고도화.

**아키텍처 결정:**
- 초기: **item-based collaborative filtering** (Python scipy / sklearn)
  - 사용자-책 평점 행렬 (완독=5, 읽는 중=3, 위시리스트=1)
  - 코사인 유사도로 가장 가까운 k개 책 추출
- 모델 주기적 재학습: APScheduler 주 1회 배치 (Redis 캐시)
- 기존 규칙 기반 3소스는 콜드 스타트 폴백으로 유지

**도메인 변경:**

```python
# discovery/service.py — RecommendationService 확장
async def get_ml_recommendations(
    self, user_id: UUID, limit: int = 10
) -> list[RecommendedBookItem]:
    # 1. Redis에서 모델 캐시 확인
    # 2. 없으면 폴백 (규칙 기반)
    # 3. 있으면 협업 필터링 결과 반환

async def retrain_model(self) -> None:
    # APScheduler에서 주 1회 호출
    ...
```

**모바일:**
- 탐색 탭 추천 섹션에 "당신만을 위한 추천" 라벨 + 이유 태그 표시

### 4.4 테스트

- `ReadingStatsService` 단위 테스트: 속도 계산, 포맷 집계, 월별 합산
- ML 추천: 콜드 스타트 폴백 검증, 중복·서재 내 책 제외 검증
- `GET /me/reading-stats` 라우터 통합 테스트

## 5. M22 — 소셜 공유 루프

### 5.1 목표

밀리의서재(연말 회고)와 북적북적(SNS 캡처)이 검증한 바이럴 공유 루프를 구현한다.

### 5.2 독서 회고 카드 (연말/상반기)

매년 12월 + 6월에 개인화된 독서 회고 카드를 생성·공유.

**카드 종류 (4종):**

| 카드 | 내용 |
|---|---|
| 올해 가장 오래 읽은 책 | 누적 독서 시간 기준 |
| 첫 완독 | 올해 가장 먼저 완독한 책 |
| 최고 두께 | 페이지 수 기준 |
| 하이라이트 왕 | 하이라이트 수 가장 많은 책 |

**백엔드:**

```
GET /me/reading-recap?period=2026-H1
  → card_type: "most_time" | "first_completed" | "thickest" | "most_highlighted"
  → book: { title, cover_url, author }
  → stat_value: str  — "총 42시간", "1월 3일", "892페이지", "하이라이트 27개"
```

**모바일:**
- 홈 탭 상단 배너: 회고 기간에만 노출
- 카드 디자인: Airbnb 디자인 시스템 + 그라디언트 배경 + 책 표지

- `RepaintBoundary`로 카드 → PNG 스냅샷 → 공유

### 5.3 서재 SNS 캡처 최적화

북적북적 방식: 서재를 보기 좋게 캡처해 SNS에 올리고 싶게 만드는 UI.

**변경 사항:**
- 서재 탭 우상단에 "📷 캡처" 버튼 추가
- 캡처 전용 레이아웃: 책 표지 그리드 + 닉네임 + 통계 요약 + Book Club 워터마크
- 캡처 크기: 정사각형(인스타 최적) / 세로형(스토리 최적) 선택
- `RepaintBoundary` → `toImage` → 갤러리 저장 또는 바로 공유

### 5.4 배지 핀 고급 UI

현재 배지 핀은 토글만 있음. 드래그 앤 드롭으로 프로필 배지 순서 변경.

**변경 사항:**

- 핀 배지 최대 6개 슬롯 시각화 (빈 슬롯 점선 표시)
- 드래그 순서를 `user_badges.pin_order` 컬럼에 저장

**백엔드:**

```

  body: { badge_ids: [uuid, uuid, ...] }  — 순서대로 pin_order 재설정
```

## 7. 아키텍처 고려사항

### 7.1 ML 모델 레이어

- 모델 학습·추론 로직은 `discovery/` 도메인 내 `ml/` 서브패키지로 격리
- `RecommendationService`는 ML 구현에 직접 의존하지 않고 `MLRecommendationPort`를 통해 호출
- 초기에는 인메모리 numpy/scipy 행렬, 사용자 10만 이상 시 별도 ML 서비스 분리 경로 확보

### 7.2 회고 카드 집계 쿼리 성능

- `GET /me/reading-recap`는 전체 독서 이력 집계이므로 Redis TTL 24시간 캐시 필수
- 회고 기간(12월/6월)에만 생성 트리거, 나머지 기간 캐시 불용

### 7.3 SNS 공유 이미지 생성

- 이미지 생성은 모바일 클라이언트에서 처리 (서버 이미지 생성 불필요)
- `RepaintBoundary` → `RenderRepaintBoundary.toImage()` → `image_gallery_saver` 또는 `share_plus`

### 7.4 보류 항목 (Phase 6 이후)

- **(club) 그룹 채팅**: WebSocket 서버(FastAPI `websockets` 또는 별도 채팅 서버) 인프라 설계 선행 필요. Phase 6에서 독립 마일스톤으로 분리.
- **(discovery) 딥러닝 추천**: 사용자 데이터 규모(최소 1만 활성 사용자) 확보 이후 검토.

## 8. 오픈 퀘스천 (결정 보류)

1. **카카오 책 API v3 쿼터**: 일간 쿼터 한도와 ISBN 정확도 실측 후 폴백 호출 비율 설계.
2. **협업 필터링 임계값**: 공통 완독 최소 몇 권이어야 유사 사용자로 간주할지 — A/B 테스트 필요.
3. **회고 카드 공개 주기**: 연 2회(6월/12월) vs 분기 1회 — 초기에는 연 2회로 시작.
4. **fl_chart 도입 여부**: 이미 의존성에 있는지 확인 후 결정. 없으면 `syncfusion_flutter_charts`(유료 무료 티어) 대비 검토.
