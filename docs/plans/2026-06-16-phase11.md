# Phase 11 — 앱 출시 후 성장 & 리텐션 최적화

## 1. 배경

Phase 10(`v0.7.0`)에서 챌린지 배지 희소성·큐레이션 카드·A/B 실험 인프라·ML 추천 고도화·앱스토어 출시까지 완성했다. 앱 버전은 `1.0.0+1`로 실제 App Store에 등록된 상태다.

**Phase 11의 전략적 맥락**:

1. **출시 직후 리텐션이 최대 과제** — 앱스토어 출시 후 D7 리텐션이 장기 성장의 핵심 지표. 이탈 징후를 조기에 감지하고 재참여를 유도하는 메커니즘이 필요하다.
2. **소셜 피드가 DAU의 핵심** — 현재 피드는 모든 활동을 동등 노출하지만, 팔로우 기반 피드와 리액션 시스템이 체류 시간을 높이는 것으로 업계 패턴이 검증되어 있다.
3. **클럽 발견이 신규 사용자 온보딩 장벽** — 공개 클럽 목록(M32)은 있으나 취향 기반 탐색이 없어 적합한 클럽을 찾기 어렵다.
4. **IAP 쉴드 구매 데이터 준비 완료** — M43 A/B 전환 데이터가 누적되면 쉴드 유료 IAP의 수익 잠재력을 검증할 수 있다.
5. **성능 모니터링 인프라 부재** — 출시 후 실 트래픽에서 P99 응답 지연·에러율을 가시화할 APM 도구가 없다.

## 3. M46 — 리텐션 & 재참여 강화

### 3.1 목표

7일 미접속 사용자를 세그먼트로 분리하여 스마트 재참여 푸시를 발송하고, 중단된 독서 스트릭을 복구할 수 있는 메커니즘을 제공한다. D7/D30 리텐션 지표를 5%p 이상 개선하는 것을 목표로 한다.

### 3.2 비즈니스 규칙

- **이탈 기준**: 마지막 로그인(`users.last_active_at`) 기준 7일 경과 시 "이탈 위험" 세그먼트로 분류.
- **재참여 푸시 조건**:
  - 알림 수신 동의 사용자에게만 발송.
  - 동일 사용자에게 7일 이내 재참여 푸시 중복 발송 금지.
  - 발송 후에도 미접속 시 14일 후 2차 발송 (최대 2회).
- **스트릭 복구 메커니즘**:
  - 스트릭이 3 이상이었다가 끊긴 경우, 복구 가능 기간 48시간.
  - 복구 조건: 목표 독서 시간의 50% 이상 달성 시 스트릭 1 복구.
  - 복구는 30일 주기에 최대 2회 허용.
  - `streak_shields`(M26)와 별개 메커니즘 — 쉴드는 자동 차감, 복구는 사용자 능동 행동 필요.
- **이탈 감지 스케줄러**: 매일 03:00 KST에 `last_active_at < NOW() - INTERVAL '7 days'` 사용자 쿼리 후 재참여 푸시 대상 선별.

### 3.3 DB 변경

```sql
-- 사용자 마지막 활동 시각 (기존 컬럼이 없다면 추가)
ALTER TABLE users ADD COLUMN IF NOT EXISTS last_active_at TIMESTAMPTZ;

-- 재참여 푸시 발송 이력
CREATE TABLE reengagement_push_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    sent_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    campaign VARCHAR(32) NOT NULL,  -- 'day7' | 'day14'
    opened_at TIMESTAMPTZ           -- 앱 재오픈 시 업데이트
);
CREATE INDEX idx_reengagement_push_user ON reengagement_push_logs(user_id, sent_at DESC);

-- 스트릭 복구 이력
CREATE TABLE streak_recovery_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    recovered_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    streak_before INT NOT NULL,
    streak_after INT NOT NULL
);
CREATE INDEX idx_streak_recovery_user ON streak_recovery_logs(user_id, recovered_at DESC);
```

### 3.4 백엔드 API 변경

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/me/streak/recover` | 스트릭 복구 시도 (48시간 이내 + 조건 충족 시) |
| GET | `/me/streak/recovery-status` | 현재 복구 가능 여부·남은 시간 |
| GET | `/admin/retention/stats` | 이탈률·재참여율·복구율 통계 |

**스케줄러**: `backend/app/workers/reengagement_scheduler.py`
- APScheduler 또는 Celery Beat으로 매일 03:00 KST 실행.
- `NotificationPort`를 통해 FCM 일괄 발송.

**도메인 레이어**:
- `backend/app/domains/notification/service.py`에 `schedule_reengagement_push()` 추가.
- `backend/app/domains/reading/service.py`에 `attempt_streak_recovery()` 추가.

### 3.5 모바일 변경

- **재참여 딥링크**: 푸시 탭 시 최근 읽던 책 타이머 화면으로 직행.
- **스트릭 복구 배너**: `HomeScreen` 상단에 스트릭 복구 가능 상태일 때 배너 노출.
  - "스트릭 {N}일이 위기에 처했어요! 오늘 목표의 50%만 달성하면 복구됩니다." 문구.
  - 배너 탭 → `TimerScreen`으로 이동.
- **`StreakRecoveryProvider`**: `GET /me/streak/recovery-status` polling (앱 포그라운드 진입 시).

## 4. M47 — 소셜 피드 강화 (팔로우 피드 + 리액션)

### 4.1 목표

현재 피드는 전체 활동을 시간순으로 보여주는 "글로벌 피드"다. 팔로우 관계 기반 피드로 전환하고, 리액션 시스템(이모지 5종)과 댓글 2뎁스를 추가하여 피드 체류 시간을 높인다.

### 4.2 비즈니스 규칙

- **팔로우 피드**:
  - 기본 탭: 팔로우한 사람들의 활동만 표시 (팔로우 없으면 추천 피드로 폴백).
  - 추천 탭: 기존 글로벌 피드 (전체 공개 활동).
  - 피드 항목은 `feed_events` 테이블(M37) 기반, `user_follows`(M7) JOIN으로 필터링.
- **리액션 시스템**:
  - 이모지 5종: 📚(읽는 중), 🔥(대단해), 💡(영감), 🎉(축하), ❤️(좋아).
  - 1사용자 1피드 항목당 1리액션 (변경 가능, 취소 가능).
  - 리액션 집계는 `feed_event_reactions` 테이블에서 실시간 COUNT.
- **댓글 2뎁스**:
  - 피드 항목에 댓글 작성 가능 (기존 1뎁스).
  - 댓글에 대댓글 1회 허용 (2뎁스 고정, 무한 뎁스 금지).
  - 댓글/대댓글 작성 시 원작성자에게 푸시 알림.
- **알림**: 내 피드 항목에 리액션·댓글 발생 시 인앱 알림 + FCM.

### 4.3 DB 변경

```sql
-- 리액션 테이블
CREATE TABLE feed_event_reactions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    feed_event_id UUID NOT NULL REFERENCES feed_events(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    emoji VARCHAR(8) NOT NULL,  -- 'book' | 'fire' | 'bulb' | 'party' | 'heart'
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(feed_event_id, user_id)
);
CREATE INDEX idx_reactions_feed_event ON feed_event_reactions(feed_event_id);

-- 댓글 테이블 (2뎁스 지원)
CREATE TABLE feed_comments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    feed_event_id UUID NOT NULL REFERENCES feed_events(id) ON DELETE CASCADE,
    author_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    parent_id UUID REFERENCES feed_comments(id) ON DELETE CASCADE,  -- NULL이면 최상위
    body VARCHAR(500) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ
);
CREATE INDEX idx_comments_feed_event ON feed_comments(feed_event_id, created_at);
CREATE INDEX idx_comments_parent ON feed_comments(parent_id);
```

### 4.4 백엔드 API 변경

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/feed?type=following\|recommended` | 팔로우/추천 피드 분기 |
| POST | `/feed/{event_id}/reactions` | 리액션 추가/변경 |
| DELETE | `/feed/{event_id}/reactions` | 리액션 취소 |
| GET | `/feed/{event_id}/comments` | 댓글 목록 (대댓글 포함) |
| POST | `/feed/{event_id}/comments` | 댓글 작성 |
| DELETE | `/feed/comments/{comment_id}` | 댓글 삭제 (본인·어드민) |

`GET /feed` 응답에 `reaction_counts: dict[str, int]`, `my_reaction: str | None`, `comment_count: int` 필드 추가.

### 4.5 모바일 변경

- **`FeedScreen`**:
  - 상단 탭바: "팔로우" / "추천" 전환.
  - `FeedCard`에 리액션 바 추가 (이모지 5종 아이콘 + 각 COUNT).
  - 롱프레스 또는 이모지 탭으로 리액션 선택 바텀시트.
- **`FeedCommentsScreen`** (신규):
  - 댓글 목록 + 대댓글 인덴트 표시.
  - 하단 고정 입력창.
  - 댓글 탭 시 `FeedCommentsScreen`으로 push.
- **`FeedProvider`**: `type` 파라미터 지원, following/recommended 상태 분리.

## 5. M48 — 클럽 발견 강화

### 5.1 목표

공개 클럽 목록(M32)에 태그/카테고리 필터와 AI 기반 클럽 추천을 추가하여 신규 사용자의 적합한 클럽 발견 시간을 단축한다.

### 5.2 비즈니스 규칙

- **클럽 태그/카테고리**:
  - 클럽 생성·수정 시 태그 최대 5개 선택 (자유 입력 + 추천 목록).
  - 추천 카테고리 목록: `소설`, `자기계발`, `경제/경영`, `역사`, `과학`, `에세이`, `인문`, `SF`, `기타`.
  - 공개 클럽 목록에서 카테고리·태그로 필터링 가능.
- **AI 기반 클럽 추천**:
  - M44의 `user_taste_profiles`(취향 프로파일)을 활용.
  - 클럽의 태그 벡터와 사용자 취향 벡터 코사인 유사도로 TOP 5 추천.
  - 추천 근거 한 줄 표시: "당신의 독서 취향({장르})과 맞는 클럽".
  - 신규 사용자(taste_profile 미생성)는 온보딩 관심사 기반 추천.
- **인기 클럽**: 최근 30일 신규 멤버 수 기준 정렬 옵션 추가.

### 5.3 DB 변경

```sql
-- 클럽 태그
CREATE TABLE club_tags (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    club_id UUID NOT NULL REFERENCES clubs(id) ON DELETE CASCADE,
    tag VARCHAR(32) NOT NULL,
    UNIQUE(club_id, tag)
);
CREATE INDEX idx_club_tags_club ON club_tags(club_id);
CREATE INDEX idx_club_tags_tag ON club_tags(tag);

-- 클럽 카테고리 컬럼 추가
ALTER TABLE clubs ADD COLUMN category VARCHAR(32);
CREATE INDEX idx_clubs_category ON clubs(category) WHERE is_public = true;
```

### 5.4 백엔드 API 변경

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/clubs/public?category=&tag=&sort=recommended\|recent\|popular` | 필터/정렬 지원 공개 클럽 목록 |
| GET | `/clubs/recommended` | AI 기반 개인화 클럽 추천 TOP 5 |
| PATCH | `/clubs/{id}` | 기존 엔드포인트에 `category`, `tags` 필드 추가 |

**추천 로직**:
- `backend/app/domains/club/service.py`에 `get_recommended_clubs()` 추가.
- `user_taste_profiles`에서 장르 벡터 조회 → `club_tags` 매칭 → 유사도 정렬.
- DB 쿼리 최적화: 추천 결과를 Redis에 1시간 캐싱 (`recommended_clubs:{user_id}`).

### 5.5 모바일 변경

- **`PublicClubsScreen`** 개편:
  - 상단 카테고리 칩 필터 바 (가로 스크롤).
  - "AI 추천 클럽" 섹션 (상단 고정, 최대 3개 카드).
  - 정렬 옵션: 최신순 / 인기순 / 추천순.
- **클럽 생성/수정 화면**: 카테고리 선택 드롭다운 + 태그 입력 필드 추가.

## 6. M49 — IAP 쉴드 추가 구매

### 6.1 목표

M26에서 구현한 독서 스트릭 쉴드를 RevenueCat IAP 소비형 상품으로 추가 구매할 수 있게 한다. 기본 쉴드(로그인 보상 등으로 획득)에 더해 유료 구매 경로를 열어 수익 다각화를 추진한다.

### 6.2 비즈니스 규칙

- **상품 구성**:
  - 쉴드 1개: 990원 (SKU: `shield_1`)
  - 쉴드 3개: 2,490원 (SKU: `shield_3`, 약 16% 할인)
- **구매 흐름**:
  1. 사용자가 쉴드 구매 UI에서 상품 선택.
  2. StoreKit 2(iOS) / Play Billing(Android)로 결제 진행.
  3. RevenueCat `POST /receipts`로 영수증 검증.
  4. 검증 성공 시 `users.streak_shields` 증가.
  5. RevenueCat PURCHASE webhook으로 서버 사이드 추가 검증.
- **구매 제한**: 1회 최대 9개 (쌓이는 상한 없음).
- **환불 처리**: RevenueCat CANCELLATION webhook 수신 시 `streak_shields` 차감 (0 미만 불가).
- Pro 구독 여부와 무관하게 구매 가능 (비구독자도 쉴드 구매 허용).

### 6.3 DB 변경

```sql
-- 쉴드 구매 이력
CREATE TABLE shield_purchases (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    sku VARCHAR(32) NOT NULL,         -- 'shield_1' | 'shield_3'
    quantity INT NOT NULL,
    amount_krw INT NOT NULL,
    revenuecat_transaction_id VARCHAR(128) UNIQUE,
    purchased_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    refunded_at TIMESTAMPTZ
);
CREATE INDEX idx_shield_purchases_user ON shield_purchases(user_id, purchased_at DESC);
```

### 6.4 백엔드 API 변경

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/me/shields/purchase` | 쉴드 구매 요청 (영수증 포함) |
| GET | `/me/shields` | 현재 보유 쉴드 수 + 구매 이력 |

**`/me/shields/purchase` 요청 본문**:
```json
{
  "sku": "shield_3",
  "platform": "ios",
  "receipt_data": "<base64 encoded JWS>"
}
```

**서비스 레이어**:
- `backend/app/domains/reading/service.py`에 `purchase_shields()` 추가.
- 기존 `RevenueCatAdapter`(M36)를 재사용하여 영수증 검증.
- webhook 핸들러(`POST /webhooks/revenuecat`)에 쉴드 구매 이벤트 처리 추가.

### 6.5 모바일 변경

- **`ShieldPurchaseSheet`** (신규 BottomSheet):
  - 쉴드 현재 보유 수 표시.
  - 상품 카드 2종 (1개 / 3개) with 가격·절감 배지.
  - `RevenueCat Flutter SDK`의 `purchasePackage()` 호출.
- **진입점**:
  - `HomeScreen` 스트릭 카드에서 쉴드 아이콘 탭 → `ShieldPurchaseSheet`.
  - 스트릭이 끊길 위험 알림 탭 시 동일 시트 열기.
- **`ShieldProvider`**: `GET /me/shields` 조회, 구매 성공 시 로컬 상태 즉시 갱신.

## 7. M50 — 성능 & 모니터링 인프라

### 7.1 목표

출시 후 실 트래픽에서 성능 문제를 조기에 감지하고 대응하는 체계를 구축한다. P99 API 응답 시간 200ms 이하를 목표 SLO로 설정한다.

### 7.2 구현 범위

#### Redis 응답 캐싱

- 조회 빈도 높고 변경이 드문 엔드포인트에 캐시 레이어 추가.
  - `GET /me/recommendations` → TTL 1시간
  - `GET /clubs/recommended` → TTL 1시간 (M48에서 부분 적용)
  - `GET /books/{id}/curation-cards` → TTL 6시간
  - `GET /social/leaderboard/weekly` → TTL 5분
- `backend/app/core/cache.py`: `cache_response()` 데코레이터 구현 (키 패턴·TTL 파라미터화).
- 캐시 무효화: 관련 데이터 변경 시 명시적 `REDIS.delete(key)` 호출.

#### Prometheus + Grafana APM

- `prometheus-fastapi-instrumentator` 미들웨어 추가.
- 수집 메트릭:
  - `http_request_duration_seconds` (히스토그램, P50/P95/P99)
  - `http_requests_total` (카운터, status_code·path 레이블)
  - `active_users_total` (커스텀 게이지, 5분 이내 활성 세션)
- `docker-compose.yml`에 Prometheus + Grafana 서비스 추가 (로컬 개발용).
- Grafana 대시보드 JSON 프리셋: `infra/grafana/dashboards/api_performance.json`.
- 프로덕션(Fly.io): Fly.io 내장 Prometheus 엔드포인트 활성화 + Grafana Cloud 연동.

#### 에러 모니터링

- `sentry-sdk[fastapi]` 추가, `DSN`은 `.env` → `SENTRY_DSN`.
- `500` 이상 에러·처리되지 않은 예외 자동 캡처.
- Flutter: `sentry_flutter` 추가, uncaught exception + ANR 캡처.

### 7.3 비기능 목표 (SLO)

| 지표 | 목표 |
|---|---|
| P99 API 응답 시간 | ≤ 200ms (캐시 히트 기준) |
| P99 API 응답 시간 | ≤ 500ms (캐시 미스 기준) |
| 에러율 (5xx) | ≤ 0.1% |
| 앱 크래시율 | ≤ 0.5% (세션 기준) |

### 7.4 백엔드 변경

- `backend/requirements.txt`에 `prometheus-fastapi-instrumentator`, `sentry-sdk[fastapi]` 추가.
- `backend/app/main.py`에 Instrumentator·Sentry 미들웨어 마운트.
- `GET /metrics` 엔드포인트 (Prometheus scrape 전용, 내부 IP 접근 제한).

### 7.5 모바일 변경

- `pubspec.yaml`에 `sentry_flutter` 추가.
- `main.dart`에 `SentryFlutter.init()` 래핑.
