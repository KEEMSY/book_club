# Book Club — Phase 7 구현 계획

## 1. 배경 및 목표

Phase 6(`v0.3.0`)에서 WebSocket 기반 실시간 채팅 인프라(M23), 그룹 채팅 UI(M24), 실시간 인앱 알림 + FCM 심화(M25)를 완료했다.

Phase 7은 **2026-06-07 시장성 및 경쟁 분석** (`docs/2026-06-07-market-analysis.md`) 결과를 직접 수용하여 **리텐션 강화**와 **바이럴 루프 상시화**에 집중한다.

분석이 식별한 핵심 리스크는 "독서 앱 리텐션 난이도"이며, 이에 대한 검증된 대응 패턴 세 가지가 Phase 7 세 마일스톤을 구성한다.

1. **M26 — 스트릭 보호 메커니즘**: Duolingo·NRC 검증 패턴인 "스트릭 쉴드"를 도입하여 이탈의 핵심 원인인 스트릭 단절을 완충한다. 쉴드는 유료 전환 트리거로도 활용될 수 있는 핵심 자산이다.
2. **M27 — 소셜 리더보드**: 팔로잉 기준 주간 독서 시간 리더보드를 도입해 NRC "친구 챌린지" 패턴을 구현한다. 자발적 공유를 통한 바이럴 루프를 유도한다.
3. **M28 — 연중 회고 카드 확장**: M22에서 구현한 반기 회고 카드(4종)를 월간 회고와 마일스톤 달성 카드로 확장한다. 연말 1회 → 연중 상시 바이럴 루프로 전환한다.

## 3. M26 — 스트릭 보호 메커니즘

### 3.1 목표

하루 독서를 놓쳤을 때 스트릭이 즉시 0으로 초기화되는 현상이 이탈의 핵심 트리거다. "스트릭 쉴드"를 도입해 1회 단절을 자동으로 흡수한다. 쉴드는 성실한 독서 습관에 대한 보상으로 적립되므로, 쉴드 소모 알림이 사용자를 당일 앱으로 재유입시키는 역할을 한다.

### 3.2 비즈니스 규칙

- **적립**: 7일 연속 스트릭 달성 시 쉴드 1개 지급 (스트릭 7, 14, 21, ... 일마다 반복).
- **상한**: 쉴드 최대 보유량은 3개. 이미 3개를 보유한 상태에서는 추가 지급 없음.
- **자동 소비**: 마지막 독서일로부터 2일이 경과한 시점(즉 하루를 건너뜀)에 쉴드 1개를 자동 소비하고 스트릭을 유지한다.
- **소비 불가**: 연속 2일 이상 놓치는 경우(마지막 독서일로부터 3일 이상 경과)에는 쉴드를 소비하지 않고 스트릭을 0으로 초기화한다. 쉴드는 최대 1일 결석만 보호한다.
- **적립 시점 검증**: 쉴드 적립은 `update_streak` 호출 후 streak_days가 7의 배수가 된 시점에 수행한다.

### 3.3 DB 변경

```sql
-- Alembic 마이그레이션
ALTER TABLE user_grades
    ADD COLUMN streak_shields SMALLINT NOT NULL DEFAULT 0
        CHECK (streak_shields >= 0 AND streak_shields <= 3);
```

기존 `UserGrade` 모델에 컬럼 추가:

```python
streak_shields: Mapped[int] = mapped_column(
    SmallInteger, nullable=False, server_default="0"
)
```

`CheckConstraint("streak_shields >= 0 AND streak_shields <= 3", name="ck_user_grades_shields_range")`를 `__table_args__`에 추가한다.

### 3.4 서비스 로직 변경

**`streak_policy.py` 확장** — `update_streak` 함수에 쉴드 소비 로직을 통합하거나, 별도 `apply_shield_protection` 순수 함수를 추가한다.

핵심 분기 (의사코드):

```
gap = session_date - previous_last_date (일 수)

if gap == 1:
    # 연속 달성 → 스트릭 +1
    new_streak = previous_streak + 1
    shields_delta = 0
elif gap == 2 and shields > 0:
    # 1일 결석 + 쉴드 보유 → 쉴드 소비, 스트릭 유지
    new_streak = previous_streak + 1   # 쉴드로 공백을 채워 +1로 처리
    shields_delta = -1
elif gap == 2 and shields == 0:
    # 1일 결석 + 쉴드 없음 → 스트릭 1로 리셋
    new_streak = 1
    shields_delta = 0
else:  # gap >= 3 or gap == 0 (same day)
    # 2일 이상 결석 또는 당일 재기록
    new_streak = 1 if gap >= 3 else previous_streak
    shields_delta = 0

# 쉴드 적립 (7일 배수 달성 시)
if new_streak % 7 == 0 and shields + shields_delta < 3:
    shields_delta += 1
```

**`UserGradeRepository` 포트 변경** — `update_snapshot` 메서드 시그니처에 `streak_shields_delta: int = 0` 파라미터를 추가한다. Repository 구현은 `streak_shields + streak_shields_delta`를 0-3 범위로 클램핑 후 저장한다.

### 3.5 API 변경

`GET /me/grade` 응답에 `streak_shields` 필드 추가:

```json
{
  "grade": 2,
  "tier": 1,
  "streak_days": 14,
  "longest_streak": 21,
  "streak_shields": 2,
  ...
}
```

`GradeSummary` DTO에 `streak_shields: int` 필드를 추가한다.

### 3.6 모바일 변경

- `GradeModel`에 `streakShields` 필드 추가.
- 등급 화면·타이머 완료 화면에 쉴드 아이콘(방패 아이콘) + 보유 수량 표시.
- 쉴드 소비 시 서버가 `UserGradeRecomputed` 이벤트를 발행하면 푸시 알림 발송: "오늘 하루 쉬었지만 스트릭 쉴드가 여러분을 지켜줬어요. 남은 쉴드: N개".

### 3.7 테스트

- 7일 달성 후 쉴드 1개 적립 확인.
- 쉴드 보유 상태에서 1일 결석 → 스트릭 유지, 쉴드 -1 확인.
- 쉴드 없는 상태에서 1일 결석 → 스트릭 1 리셋 확인.
- 2일 이상 결석 + 쉴드 보유 → 쉴드 소비 없이 스트릭 리셋 확인.
- 쉴드 3개 보유 시 추가 적립 없음 확인.
- 단위 테스트: `streak_policy` 순수 함수에 Fake 없이 직접 검증.

## 4. M27 — 소셜 리더보드

### 4.1 목표

팔로잉 기준 주간 독서 시간 랭킹을 제공한다. 경쟁보다는 "내 커뮤니티의 독서량"을 확인하는 소셜 확인 경험을 지향한다. NRC의 "친구 챌린지"와 유사하나, 챌린지 신청 없이 상시 제공되는 점이 다르다.

### 4.2 API 설계

```
GET /social/leaderboard/weekly
```

**쿼리 파라미터**:
- `year` (optional, int): 기준 연도. 기본값은 현재 연도.
- `week` (optional, int): 기준 ISO 주차(1-53). 기본값은 현재 주차.

**응답**:

```json
{
  "week_start": "2026-06-01",
  "week_end": "2026-06-07",
  "entries": [
    {
      "rank": 1,
      "user_id": "...",
      "display_name": "김독서",
      "profile_image_url": "...",
      "weekly_seconds": 14400,
      "is_me": false
    },
    ...
  ],
  "my_rank": 3,
  "my_weekly_seconds": 7200
}
```

**비즈니스 규칙**:
- 나를 포함하여 내가 팔로우하는 사용자만 집계 대상.
- 공개 프로필(visibility=public) 사용자만 포함. 비공개 사용자는 집계에서 제외.
- 동점인 경우 이름 가나다 순으로 정렬.
- 리더보드는 `daily_reading_stats` 집계에서 주간 범위(ISO 주 기준)를 합산하여 계산.
- 결과는 Redis에 5분 TTL로 캐싱 (팔로우 그래프 변경 시 캐시 무효화).

**레이어 배치**:
- Router: `social` 도메인 (`app/domains/social/router.py`)
- Service: `SocialService.get_weekly_leaderboard(user_id, week_start, week_end)`
- Repository: `DailyStatRepositoryPort`의 신규 메서드 `weekly_sum_for_users(user_ids, from_date, to_date) → dict[UUID, int]`

### 4.3 모바일 변경

- 피드 탭 하단 또는 소셜 탭에 "이번 주 독서 랭킹" 카드 추가.
- `LeaderboardScreen`: 순위 목록 + 내 순위 하이라이트.
- 순위 변동(+N, -N) 표시 (이전 주 대비).

### 4.4 테스트

- 팔로잉 3명 + 본인 → 최대 4명 리더보드 반환 확인.
- 비공개 계정은 목록에서 제외 확인.
- 동점 처리: 동점 시 이름 순 정렬 확인.
- Redis 캐싱: 동일 요청 2회 → 두 번째는 캐시 히트 확인.

## 5. M28 — 연중 회고 카드 확장

### 5.1 목표

M22에서 구현된 반기/연말 회고 카드(4종: 가장 많이 읽은 책, 첫 완독, 가장 두꺼운 책, 하이라이트 최다)를 확장한다. 월간 회고와 마일스톤 달성 카드를 추가하여 연말 1회 이벤트를 연중 상시 바이럴 루프로 전환한다.

### 5.2 월간 회고 API

```
GET /me/recap/monthly?year=YYYY&month=M
```

**응답**:

```json
{
  "year": 2026,
  "month": 6,
  "total_books": 3,
  "total_seconds": 54000,
  "total_minutes": 900,
  "best_day": {
    "date": "2026-06-15",
    "seconds": 7200
  },
  "streak_peak": 12,
  "cards": [
    {
      "card_type": "most_time",
      "title": "채식주의자",
      "cover_url": "...",
      "author": "한강",
      "stat_value": "총 8시간"
    }
  ]
}
```

**구현 상세**:
- `from_date = date(year, month, 1)`, `to_date = 해당 월 마지막 날`.
- 기존 `get_reading_recap` 로직을 `period` 포맷 대신 월 범위로도 호출할 수 있도록 내부 헬퍼를 추출한다.
- `streak_peak`: 해당 월 기간 중 최장 스트릭 (DailyReadingStat 연속 유무로 계산).

### 5.3 마일스톤 달성 카드 API

```
GET /me/recap/milestones
```

**응답**:

```json
{
  "milestones": [
    {
      "id": "BOOKS_5",
      "label": "책 5권 완독",
      "achieved_at": "2026-05-03",
      "is_new": false
    },
    {
      "id": "HOURS_10",
      "label": "총 10시간 독서",
      "achieved_at": "2026-04-20",
      "is_new": false
    },
    {
      "id": "STREAK_30",
      "label": "30일 연속 독서",
      "achieved_at": null,
      "is_new": false
    }
  ]
}
```

**마일스톤 종류**:

| ID | 달성 기준 | 데이터 출처 |
|---|---|---|
| `BOOKS_5` | total_books >= 5 | user_grades.total_books |
| `BOOKS_10` | total_books >= 10 | user_grades.total_books |
| `BOOKS_20` | total_books >= 20 | user_grades.total_books |
| `HOURS_10` | total_seconds >= 36000 (10h) | user_grades.total_seconds |
| `HOURS_50` | total_seconds >= 180000 (50h) | user_grades.total_seconds |
| `HOURS_100` | total_seconds >= 360000 (100h) | user_grades.total_seconds |
| `STREAK_30` | longest_streak >= 30 | user_grades.longest_streak |

**구현 방침**:
- 별도 `user_milestones` 테이블을 두어 최초 달성일을 기록한다.
- `UserGradeRecomputed` 이벤트 구독자에서 새로 달성된 마일스톤을 감지하면 `user_milestones`에 INSERT한다.
- `achieved_at`은 마일스톤 행이 없으면 `null`, 있으면 최초 달성일.
- `is_new`: 달성 후 24시간 이내이면 `true` (모바일 축하 애니메이션 트리거).

**신규 테이블**:

```sql
CREATE TABLE user_milestones (
    user_id      UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    milestone_id VARCHAR(32) NOT NULL,
    achieved_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY  (user_id, milestone_id)
);
CREATE INDEX ix_user_milestones_user_id ON user_milestones (user_id);
```

### 5.4 모바일 변경

**마일스톤 축하 트리거**:
- `UserGradeRecomputed` WS 이벤트 페이로드에 `new_milestones: list[str]` 필드를 추가한다.
- 모바일은 목록이 비어있지 않으면 축하 오버레이(Lottie 애니메이션) + 회고 카드 공유 버튼을 띄운다.

**월간 카드 공유**:
- 월간 회고 화면에서 "카드 공유" 버튼 → `RepaintBoundary` 캡처 → `share_plus` 공유 시트 (M22 패턴 재사용).
- 공유 카드 디자인: 월/연도 헤더 + 주요 통계 2줄 + 브랜드 워터마크.

### 5.5 테스트

- `BOOKS_5` 달성 시 `user_milestones` 행 생성, `achieved_at` 정확도 확인.
- 동일 마일스톤 중복 달성 없음 확인 (INSERT ON CONFLICT DO NOTHING).
- `is_new`: 달성 25시간 후 `false`로 전환 확인.
- 월간 회고: 해당 월 데이터 없을 때 빈 cards 반환 확인.
- WS 이벤트에 `new_milestones` 필드 포함 확인.

## 7. 아키텍처 고려사항

### 7.1 streak_policy 순수 함수 원칙 유지

`streak_policy.update_streak`는 현재 순수 함수 (`previous_last_date, previous_streak_days, longest_streak, session_date → (streak_days, longest_streak, last_date)`)로 구성되어 단위 테스트가 용이하다. M26에서 쉴드 파라미터를 추가할 때도 이 순수 함수 인터페이스를 유지한다. 반환 타입을 `NamedTuple` 또는 `dataclass`로 확장하여 `shields_delta`를 포함시킨다.

### 7.2 소셜 리더보드 Redis 캐싱 전략

리더보드 쿼리는 팔로우 그래프 크기에 따라 최대 수백 명의 `user_id`를 `daily_reading_stats`에서 합산해야 한다. Redis 캐시 키는 `leaderboard:weekly:{user_id}:{iso_year}:{iso_week}`로 구성하고, TTL은 5분으로 설정한다. 팔로우/언팔로우 이벤트 발생 시 해당 사용자의 캐시를 즉시 무효화한다.

### 7.3 user_milestones 이벤트 구독자

`UserGradeRecomputed` 이벤트 구독자가 이미 M5에서 등록되어 있다. M28에서는 해당 구독자에 마일스톤 달성 감지 로직을 추가하거나, 별도 `MilestoneEventHandler`를 등록한다. 후자가 단일 책임 원칙 측면에서 더 바람직하다.

### 7.4 보류 항목 (Phase 8 이후)

- **(club) 챕터별 진도 채팅방**: 현재 그룹 채팅은 책 단위 피드 구조를 가진다. 진도 기반 세분화는 user_books.progress 필드 연동 및 별도 room 타입이 필요하다. Phase 8에서 그룹 채팅 사용 패턴 분석 후 설계한다.
- **(community) 오프라인 독서 모임 연결**: 지역 기반 매칭 인프라 필요. Phase 8 이후 사용자 밀도 확보 시 재검토.
- **(discovery) 딥러닝 추천**: `user_event_log`는 M23부터 수집 중. 활성 사용자 1만 명 이상 + 6개월 이상 데이터 누적 후 진행.

## 8. M29 — 챕터별 진도 채팅방

### 8.1 목표
"3장까지 읽은 사람만 입장 가능한 스포일러 없는 토론방" — StoryGraph·Fable이 구현하지 못한 차별 기능.
현재 그룹 채팅은 클럽 단위 단일 채널이다. M29에서는 진도 기반 채팅방을 추가한다.

### 8.2 DB 변경
- club_rooms 테이블: id(UUID PK), club_id(FK), name(VARCHAR), progress_gate(SMALLINT, 0=없음, N=N장 이상만 입장), created_by(FK), created_at
- club_messages에 room_id(UUID FK club_rooms, nullable) 컬럼 추가 (NULL = 기존 클럽 전체 채팅)

### 8.3 API 설계
- POST /clubs/{club_id}/rooms — 방 생성 (클럽 오너/매니저만)
- GET  /clubs/{club_id}/rooms — 방 목록 + 입장 가능 여부 (caller의 user_books.progress 대조)
- DELETE /clubs/{club_id}/rooms/{room_id}
- WS  /ws/clubs/{club_id}/rooms/{room_id}?token=JWT — 기존 WS 패턴 확장
- POST/GET /clubs/{club_id}/rooms/{room_id}/messages — 기존 메시지 엔드포인트 확장

입장 가능 여부: user_books에서 해당 클럽의 책 progress >= progress_gate 인 경우만 허용.

### 8.4 모바일 변경
- 클럽 채팅 화면에 "채팅방 목록" 탭 추가
- 잠긴 방 표시: 자물쇠 아이콘 + "N장 이상 읽어야 입장 가능"
- 입장 가능 방은 바로 접속, 불가 방은 안내 다이얼로그

## 9. M30 — 오프라인 독서 모임 연결

### 9.1 목표
온라인 독서 그룹을 오프라인 모임으로 연결한다. 클럽 오너/매니저가 모임 일정을 등록하고, 멤버가 참석 의사를 표시한다.

### 9.2 DB 변경
- club_events 테이블: id(UUID PK), club_id(FK), title(VARCHAR), description(TEXT), event_at(TIMESTAMPTZ), location(VARCHAR), max_attendees(SMALLINT nullable), created_by(FK), created_at
- event_attendees 테이블: event_id(FK), user_id(FK), status(VARCHAR: going/maybe/not_going), PRIMARY KEY(event_id, user_id)

### 9.3 API 설계
- POST /clubs/{club_id}/events — 이벤트 생성 (오너/매니저)
- GET  /clubs/{club_id}/events — 이벤트 목록 (upcoming 우선)
- GET  /clubs/{club_id}/events/{event_id}
- PATCH /clubs/{club_id}/events/{event_id} — 수정
- DELETE /clubs/{club_id}/events/{event_id}
- POST /clubs/{club_id}/events/{event_id}/rsvp — 참석 의사 { status: going|maybe|not_going }
- GET  /clubs/{club_id}/events/{event_id}/attendees

### 9.4 모바일 변경
- 클럽 상세 화면에 "모임" 탭 추가
- 이벤트 카드: 날짜/시간, 장소, 참석자 수, RSVP 버튼
- 이벤트 생성 다이얼로그 (오너/매니저용)

## 10. 오픈 퀘스천

1. **쉴드 유료화 여부**: 쉴드 추가 구매(현재 무료 적립만)를 인앱 결제로 제공할 것인가? — 수익화 실험 대상으로 Phase 8에서 결정. Phase 7에서는 무료 적립만 구현.
2. **리더보드 공개 범위**: 비공개 사용자 제외 외에, 사용자가 개별적으로 "리더보드 노출 제외" 설정을 원할 경우 대응 방안 — Phase 7에서는 공개/비공개 계정 구분만 적용.
3. **마일스톤 커스텀 공유 카드 디자인**: M22 공유 카드 디자인을 그대로 재사용할지, 마일스톤 전용 디자인을 새로 제작할지 — UI/UX 검토 후 M28 스프린트 초반에 결정.
